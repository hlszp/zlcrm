# 工艺知识与批次寻优模块设计

## 目标

建立“配方版本 → 批次执行 → 参数实测 → 质量结果 → 异常复盘 → 改进验证 → 新版本发布”的独立闭环。模块复用合同、来料批次、炉次、设备和质检，不替代生产与财务系统。

## 范围与边界

- 支持人工录入、草稿、审核、附件、异常和版本差异。
- 不宣称设备实时联网或自动控制；监控反映人工记录的时效性和偏差。
- 不用少量数据自动给出生产参数结论；分析结果必须能回到批次证据。
- 历史批次永久绑定执行时的版本快照，已发布版本不可直接修改。

## 核心对象

- 工艺配方：特定工艺、材料、工件类别和设备适用范围下的参数集合。
- 配方版本：配方的不可变快照及审核发布记录。
- 工艺执行批次：某炉次实际执行某版本的记录，关联合同和质量。
- 参数定义：编码、名称、工序、类型、单位、必填和排序。
- 参数实测值：目标、上下限、实际数值/文本、异常状态、记录人和时间。
- 工艺事件：工序开始结束、调整、停机、返工及证据。
- 改进专题：问题、假设、对照、试验、结论和发布版本。

## 状态模型

配方版本：草稿 → 待审核 → 已发布 → 已停用。只有 admin 可发布；engineer 可创建和编辑未发布版本。

执行批次：草稿 → 待审核 → 已审核 → 已作废。已审核记录的修改必须形成审计记录。

## 数据质量

- 数值参数使用标准单位，同时保留原始文本和附件证据。
- 实际值超出上下限只标记异常，不擅自修改数值。
- 区分缺失、估读、正常和异常；空值不能当成 0。
- 样本不足时只给描述性统计，不给虚假的寻优结论。

## 分析能力

1. 批次/版本参数、质量、周期和成本对比。
2. 趋势、均值、极值、标准差、超限和异常 Pareto。
3. 标杆批次与改进前后对照。
4. 改进专题记录问题、假设、变量、试验、结论和版本发布。

## 角色

- admin：全部配置、审核发布和管理员操作。
- engineer：配方、版本、批次审核、分析和改进专题。
- manager：批次录入、提交和异常处理。
- sales/finance：只读与各自业务相关的信息；老板使用 admin 移动端只读视图。

## 页面

独立“工艺寻优”模块包含：配方版本、批次记录、过程监控、对比分析、改进专题。移动端仅增加异常、待审核和改进效果摘要。

## 实施阶段

- M1：配方、参数定义、版本审核发布和独立页面。
- M2：批次执行、参数实测、事件、审核和过程监控。
- M3：批次/版本分析、改进专题、移动端摘要和线上验收。

## 验收

- 已发布版本不可改，历史批次不受后续版本影响。
- 参数单位、异常、审核、权限和演示隔离均由后端执行。
- 每个分析结论可追溯到批次、版本和实测证据。
- 改进前后质量与成本可比较，且能选择是否形成新版本。
