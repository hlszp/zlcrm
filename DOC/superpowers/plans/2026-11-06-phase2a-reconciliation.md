# Phase 2A Reconciliation Implementation Plan

**Goal:** 统一合同余额、未排期和待核销口径，建立合同变更与审计基础。

**Spec:** `docs/superpowers/specs/2026-11-06-pvd-crm-upgrade-design.md`

## Tasks

1. 新增 `finance.py`，以合同为中心计算合同额、计划额、计划已收、实收、有效开票、未排期、未分配收款、未收和未开票；所有金额保留两位小数。
2. 仪表盘、老板、财务、移动看板使用同一余额来源，新增未排期与待核销指标；账龄新增“未排期”桶，不能把它伪装成逾期或未来回款。
3. 新增 `audit_logs`、`contract_changes`，合同更新记录前后值、原因、操作者与时间；有收款或发票时改价必须填写变更原因，且新合同额不得低于已收或有效开票。
4. 真实 Flask API 回归覆盖现有临时合同未排期、正式/演示隔离、无计划与部分计划、变更原因、余额下限、审计写入和移动端字段。
5. 备份并迁移现有数据库，运行三种模式的全接口与导出回归；不改变已有业务金额。

## Constraints

不新增依赖或测试脚手架；使用临时数据库和内联断言。核销和红冲属于 Phase 2B，不在本切片中提前改变支付/发票数据结构。
