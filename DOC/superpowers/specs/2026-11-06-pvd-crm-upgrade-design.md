# PVD 工厂 CRM 四阶段升级设计

## 目标与边界

在保留现有 Flask、SQLite、原生 JavaScript 和既有数据的前提下，把系统从演示台账升级为可追溯的合同财务与 PVD 经营系统。顺序固定为：止损 → 对账 → 行业流程 → 经营分析。老板移动端与后端共用认证、权限和指标接口，采用可安装移动 Web/PWA，不建设第二套数据源，不离线缓存敏感经营数据。

## 总体原则

- 正式数据默认隔离演示数据；仅管理员可在当前会话切换正式/演示/全部模式。
- 金额以分为存储目标；迁移期间保留现有 REAL 字段，在接口边界统一校验有限数值并保留两位小数，后续阶段再完成字段迁移。
- 财务单据不因界面隐藏而获得权限，后端逐接口校验角色与数据归属。
- 已发生收款、开票、发货或变更的合同不能无痕改价或删除；第二阶段以作废、红冲、反审核和审计日志替代硬删除。
- 所有统计必须区分合同未收、未排期、已到期、逾期、预收待核销、已开票未收和已收未开票。
- 移动端是老板只读驾驶舱与审批入口，不复制桌面端全部录入功能。

## 第一阶段：止损

### 权限与安全

角色边界：admin 全量；sales 管理本人客户、合同和发货，可登记本人合同收款；finance 管理财务计划、收款、发票和报表；manager 管理生产发货，只读合同财务数据。发货详情按合同归属校验。生产角色不得操作财务单据，财务角色不得修改合同明细或创建发货。

移除固定 Flask 密钥；开发环境未配置时生成随机密钥，生产模式必须通过 `CRM_SECRET` 提供。生产模式开启 Secure Cookie。新数据库初始管理员密码从 `CRM_ADMIN_PASSWORD` 读取或随机生成，不再使用固定密码。提供管理员安全配置状态接口，不返回秘密值。

### 业务约束

- 收款期次必须属于合同；金额必须有限且大于零；不得超过期次或合同剩余。允许不指定期次的收款，第二阶段标记为待核销。
- 发票号码不可重复，累计有效开票不得超过合同额；仅 admin/finance 可登记、作废。
- 合同明细数量必须大于零，单价和金额不得为负；合同发货必须引用本合同明细且累计发货不得超过合同数量。
- 临时发货先完整校验，再在单个事务内创建合同、明细、回款计划和发货单。新临时合同默认按发货日 +30 天生成全额计划。
- 发货单号、临时合同号使用数据库计数器，避免删除后重号及并发冲突。

### 演示隔离与云端

客户、合同、产品、服务、发货及所有关联列表、看板、报表默认只统计正式数据；管理员的会话级数据模式决定可见范围。直接详情和写操作同样受数据模式约束。核查 CloudBase 登录、实际环境、云托管磁盘、数据库与附件位置、备份调度和恢复能力；未登录时明确标记未核验，不把本地脚本等同于云端备份。

## 第二阶段：对账

新增统一余额服务，所有桌面和移动指标共用。临时或无计划合同进入“未排期应收”，不再从账龄和预测中静默消失。合同金额变化生成版本与变更记录，并给出未收期次调整差额。收款支持预收、核销、取消核销和超额转出；发票支持红冲、部分红冲与重开。所有关键写操作记录操作者、时间、对象、前后值和原因。归档合同及其收付款使用一致过滤口径。

## 第三阶段：PVD 行业流程

建立来料批次、工件/图纸版本、收货清点与照片、前处理、排产、炉次、检验、返工/报废、送回、签收、验收和月度对账。发货与来料数量可核对，质量报告和签收附件关联合同及批次。状态流转由实际批次与验收数据驱动，不再只依赖手工合同状态。

## 第四阶段：经营分析

按合同、炉次、工艺归集电费、靶材气体、人工、挂具摊销、检测、运输、外协、返工与赔偿成本，输出含税/未税收入及毛利。增加炉子利用率、准时交付率、一次合格率、返工率、客户集中度、复购、信用额度与逾期停接/停发风险。预测只基于明确的应收计划和验收/对账状态，并单独展示未排期及逾期风险。

## 老板移动端

提供 `/mobile` 入口和 manifest，适配 iOS/Android 浏览器添加到主屏幕。首屏展示本月签约、回款、合同未收、逾期、未开票、未来 90 天和风险清单；支持数据下钻到客户/合同，但不允许绕过角色权限。第二阶段加入合同变更和财务审批，第三、四阶段加入交付质量与毛利指标。敏感 API 响应禁止缓存，PWA 不预缓存业务数据。

## 验证策略

每个阶段使用临时数据库执行真实 Flask API 回归，不污染当前数据；覆盖越权、跨合同核销、超收、超开、超发、非法数值、演示隔离、统计一致性和移动端角色。云端部署后再验证重启/重新部署后的数据库与附件保留、备份恢复和手机完整流程。

## 实施假设

- 用户已确认四阶段内容与顺序；采用当前会话内直接实施，不另建独立原生 App 或前端框架。
- 在云端账号未登录前，只完成本地持久化风险修正和核查清单，不声称云端已核验。
- 不主动提交 Git、不部署或变更云端资源；需要这些外部操作时另行确认。
